# 프로젝트 기본 규칙

가상 회사 Gapsang Korea 의 사내 좌석 예약 API. **백엔드 입문자의 학습용 MVP** 다.
NestJS 11 · Prisma 6 · MySQL 8.4(Docker, 호스트 포트 3307) · pnpm 10 · Node 22 · TypeScript 5.9.

## 먼저 읽을 것

- 기능·규칙의 기준: `docs/DOMAIN.md` (비즈니스 규칙 R1~R8, ERD, API 표). 구현 전에 읽고, 구현 후 갱신한다.
- 남은 점검 항목: `docs/REVIEW.md`. 항목은 번호로 부른다 (예: "REVIEW 3번").
- 단계(1~6)와 끝났다는 기준, 진행 규칙: `README.md`.
- 범위 밖 기능 요청은 코드가 아니라 `docs/ROADMAP.md` 에 적는다. MVP 범위는 DOMAIN.md 가 기준이다.

## 학습용 저장소라서 지키는 것

- **1~2단계 영역은 사용자가 직접 작성한다** (README 진행 규칙 1). `src/floors/**`, `prisma/schema.prisma` 의 TODO 를 대신 구현하지 않는다. 설명·힌트·리뷰는 해도 된다. 사용자가 REVIEW 항목 처리 등으로 명시적으로 요청하면 그때 수정한다. 편집 훅이 이 경로 앞에서 한 번 더 묻는다.
- `docs/TERMS.md` 의 "용어 정리", README 의 "실험 기록" 은 사용자가 채우는 칸이다. 초안은 채팅으로 주고 파일에는 쓰지 않는다.
- 완성본으로 표시된 파일(`src/common/utils/date.ts`, `src/health/**`, `scripts/*.ts`)은 REVIEW 항목이 아니면 고치지 않는다.
- 사용자는 백엔드가 처음이다. 결정을 부탁하기 전에 **배경 → 선택지의 장단점 → 추천** 순서로 쉬운 말로 설명한다. 선택지만 나열하고 고르라고 하지 않는다.
- 새 용어가 나오면 한 줄 정의를 붙이고 TERMS.md 후보라고 알려 준다 (`/term <용어>` 로 초안을 만들 수 있다).
- 코드 주석의 `TODO [n단계]` 는 `pnpm todo` 가 찾는 표식이다. 구현 전에는 지우지 않는다. 비즈니스 규칙을 구현한 줄에는 `// R2` 처럼 규칙 번호를 남긴다.

## 비밀 정보

- `.env` 는 절대 커밋·출력하지 않는다. 설정 예시는 `.env.example` 에만 적고 값은 플레이스홀더로 둔다.
- 공개 저장소다. 로컬 개발용 기본 계정(app / app1234)만 들어갈 수 있고 실제 키·토큰·외부 호스트 주소는 넣지 않는다. 커밋 전 훅이 비밀 정보 패턴을 검사한다.

## 언어

- 대화·문서·커밋 메시지·주석은 한국어. 코드 식별자는 영어.
