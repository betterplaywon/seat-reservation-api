# 기능별 검증 시나리오

기능 하나에 파일 하나. "실제 서버에 무엇을 보내면 무엇이 돌아와야 하는가" 를 적는다. 테스트 코드가 아니라 사람이나 에이전트가 따라 하는 절차다.
같은 내용을 자동으로 돌리는 테스트는 `test/e2e/<이름>.e2e.mjs` 에 둔다. 시나리오가 먼저고, 반복해서 확인할 가치가 있으면 E2E 로 옮긴다.

| 파일 | 기능 | 단계 | 자동화(E2E) |
|---|---|---|---|
| `health.md` | 헬스체크 | 1 | `test/e2e/health.e2e.mjs` |

## 파일 형식

```markdown
# <기능 이름>

- 규칙: docs/DOMAIN.md 의 R번호
- 준비: 필요한 데이터(마이그레이션, 시드, 계정)

## 시나리오

1. 요청 (curl 한 줄) → 기대하는 상태 코드와 응답
2. 실패 경로도 적는다 (400·401·403·404·409)

## 증거로 남길 것

PR 본문 4번에 붙일 명령과 응답.
```

## 서버 띄우기

```bash
pnpm build
PORT=3011 node dist/main
```

다른 터미널(또는 백그라운드)에서 `curl -s -w '\n%{http_code}\n' localhost:3011/<경로>` 로 확인하고, 끝나면 내가 띄운 PID 만 종료한다.
